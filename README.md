Site structure (generated by `scripts/generate-static.mjs` from `scripts/lib/site-model.mjs` + `scripts/lib/render.mjs`):
- `/models/<family>/`: full code table per appliance model family (`40` pages, families with 3+ codes).
- `/codes/<slug>/`: one page per brand + appliance type + code, comparing what each model's manual says (`429` pages). The shortest existing slug stays canonical; the other `435` per-model URLs are noindex instant redirects to the model's row (`#<entry-id>`).
- `/brands/<brand>/`, `/guides/`, `/symptoms/<slug>/`: brand hubs, guide index, and guides.
- Detail pages are static HTML + CSS with no app bundle. The React app only runs the homepage search (`#search-app`, `?q=` supported), part capture, and the not-found page.
- Every corpus entry must belong to a model line in `src/data/families.json`; `npm run validate:corpus` fails otherwise. Add a new line (name + exact `modelFamilies`) when adding codes for a new model.
